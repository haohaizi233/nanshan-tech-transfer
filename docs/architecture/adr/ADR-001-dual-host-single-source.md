# ADR-001 · 双宿主、单代码源（Dual-Host, Single Code Source）

> 状态：已冻结（Frozen，2026-09-02 冻结评审通过，决议见 10-freeze-review.md；此后只增不改）
> 日期：2026-09-02
> 决策人：科转通架构组
> 影响范围：前端工程结构、构建流程、上级集成方式

---

## 1. 背景与问题

科转通最终要以**源码合并**方式嵌入上级"Ai南山"微信小程序（不是小程序跳转）。但当前（2026-09-02）：

1. 上级 Ai南山 源码尚未拿到；
2. 上级 Token、网关、上传、消息规范均未提供；
3. 科转通必须**现在**就能在本地独立运行、开发和联调。

由此产生一个尖锐的工程问题：**如果为"今天能跑"建一套代码、为"明天能合并"再建一套代码，合并日必然出现两套业务代码的同步地狱。**

现状源码恰好处于这个危险边缘：11 个业务页面全部挂在本地主包 `pages/`、`packageA/` 下，与本地 TabBar、本地登录（`user.js` 本地缓存账号体系）直接耦合（见 `01-current-state-audit.md` §10、§11）。

## 2. 决策

采用**双宿主、单代码源**：

```text
本地开发宿主（最小壳）───┐
                        ├──→ 同一份科转通业务分包 subpackages/tech-transfer
Ai南山 宿主（未来）──────┘
```

1. **唯一业务代码源**是 `subpackages/tech-transfer/`：11 个业务页面、组件、API 客户端、请求/响应模型、状态机常量全部只在这一份里。
2. 本地开发宿主是一个**最小主包**：仅提供 App 入口、dev-home 页、`pages.json` 分包注册、`LocalAdapter` 注册和环境配置，不承载任何业务逻辑。
3. 宿主差异（身份凭证、请求通道、上传、导航、消息、埋点）全部通过 `HostBridge` 契约隔离（见 `03-frontend-dual-host-design.md` §4）。
4. 未来合并上级时**迁移的是同一份分包目录**，替换的是宿主层（App.vue/main.js/pages.json 合并、Adapter 替换、环境配置切换）。业务分包目录内**一行代码都不改**（极端情况下的合并冲突例外见 §5）。

## 3. 备选方案与否决理由

| 备选方案 | 描述 | 否决理由 |
|----------|------|----------|
| 两套工程（独立版 + 嵌入版） | 独立小程序保留现有 `pages/`，另复制一份改为分包 | 双倍维护成本；bug 修两遍；违反"禁止维护两套业务页面"的强制约束 |
| 小程序跳转（navigateToMiniProgram） | 科转通保持独立小程序，Ai南山 跳转进入 | 需求方明确要求源码合并，且跳转无法共享登录态和视觉一致性 |
| 业务代码留在主包，用编译开关裁剪 | `pages/` 保留在主包，构建时按 HOST_MODE 裁剪 | 主包体积约束；页面路径变化导致分享/收藏路径失效；`if (isLocal)` 会散落各处，违反禁止事项 #8 |

## 4. 后果

**正面：**
- 从分包改造完成之日起，"本地版"与"嵌入版"的差异被压缩到宿主层 + Adapter 两个文件级别；
- 合并上级的工程工作量从"重写页面"降为"注册分包路由 + 实现 AiNanshanAdapter"；
- 日常开发的任何 bug 修复天然同时作用于两个宿主。

**负面与代价：**
- 一次性迁移成本：现有 11 个页面要从 `pages/`、`packageA/` 迁入 `subpackages/tech-transfer/pages/`，路径变化导致本地缓存的旧页面路径、分享路径失效（一期无线上用户，可接受）；
- 业务分包内禁止 import 本地主包模块（如 `common/user.js`），所有对宿主的依赖必须走 HostBridge，开发心智成本略增；
- 本地宿主 TabBar 与未来上级 TabBar 是两个东西，业务分包不能依赖 TabBar 导航（只能用 `HostBridge.navigate`）。

## 5. 合规检查项（评审时逐条核对）

1. 业务页面文件是否只存在于 `subpackages/tech-transfer/` 一处？
2. 业务分包内是否出现 `import '@/common/user.js'` 这类主包引用？（必须为 0）
3. 页面内是否出现 `uni.request` 直调？（必须为 0，走 HostBridge.request）
4. 页面内是否出现 `if (isLocal)` / `if (HOST_MODE === 'local')`？（必须为 0）
5. `staging/production + HOST_MODE=local` 构建是否失败？（见 02 §8.3）
