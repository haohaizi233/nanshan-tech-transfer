# 09 · 风险登记册（Risk Register）

> 文档状态：基线版
> 评级口径：概率 × 影响 = 高/中/低（高=需主动缓解并有应急预案；中=有缓解措施定期复查；低=记录观察）
> 责任角色：一期按 架构/前端/后端/数据/项目组 划分（人员指派后补名）
> 与其他文档的引用关系：01 §10（安全问题）→ 本册 R-02/R-09/R-12；05 §3.5（完成人拆分）→ R-05；08（上级待确认）→ R-01

## 2. 逐项明细

### R-01 上级四项硬前置信息缺失（对应 08 清单 C-01/C-03/C-08/C-10）

- **描述**：阶段 D 的四个硬前置（上级源码、Token 格式、网关身份传递、数据库资源）至今无一项确认。若持续缺失，本地开发可推进但正式集成无限期顺延。
- **缓解**：① 按 08 §4 **立即发函**确认四项；② AiNanshanAdapter 已按"稳定抽象接口"预置骨架，确认后仅实现协议层；③ 环境保护（02 §8.3）保证缺确认项时 staging/production 无法用 Mock 顶替上线。
- **应急预案**：若阶段 D 前仍未取得上级源码，本地宿主持续演进为"演示宿主"用于需求方演示，但**冻结**新增上级耦合功能，避免返工扩大。
- **触发信号**：阶段 B 里程碑（本地主链路全绿）达成后 30 天内未收到任一项确认。

### R-02 演示期安全债带病上线（01 §10 S1–S9）

- **描述**：明文密码本地缓存（S1）、无凭证会话（S2）、前端比对手机号判定归属（S3）、CORS 全开+SQL 错误外泄（S5）等九项。任何一项进入正式包即为生产事故级隐患。
- **缓解**：① 阶段 B 第 ⑧ 步强制退役 `user.js`/`mock-data.js`（03 §3.3），git 层面删除而非注释；② 阶段 E 安全测试逐项对照 S1–S9 销项；③ 新代码评审清单含"禁止 uni.setStorageSync 存业务事实"条目。
- **应急预案**：若演示宿主需继续对外演示（阶段 D 前），演示构建保留演示数据但**不带真实用户输入路径**（只读演示账号）。
- **触发信号**：阶段 B 结束时 `rg "ns_user_accounts|password" 南山/` 仍有业务命中。

### R-03 双代码源回潮

- **描述**：压力之下（如"嵌入版来不及，先在独立版改"）出现第二套页面或页面内 `if (isLocal)` 分支，直接摧毁 ADR-001 的合并前提。
- **缓解**：① ADR-001 §5 五条合规检查项进 PR 评审模板；② CI 静态扫描 `subpackages/tech-transfer/` 内禁止出现 `isLocal`、`uni.request`、主包 import 三种模式（与 ADR-003 §5.3 同一护栏脚本）；③ 目录即边界——新页面只允许建在分包内。
- **应急预案**：发现违例 → 当日回滚违规 PR，功能在分包内重做。
- **触发信号**：CI 扫描规则命中即失败（不存在延后处理）。

### R-04 模块化单体边界腐化

- **描述**：单体无网络边界强制，"顺手跨模块查表"逐渐把 15 个模块糊成一个大泥球，未来拆分成本剧增（ADR-003 的核心风险）。
- **缓解**：① CI import 扫描（achievement→cooperation 等反向依赖即失败）；② 跨模块只能走 service 门面；③ 每双周架构巡检依赖图与 02 §7 比对。
- **触发信号**：任一 PR 需要修改 02 §7 依赖图才能通过评审。

### R-05 223 条成果数据缺失与清洗质量

- **描述**：需求方陈述的 223 条成果数据**不在当前仓库**（01 §1 盘点确认），且按经验该类数据完成人多为"姓名1、姓名2"合并文本、成熟度为自由文本。数据获取不到则阶段 C 阻塞；清洗质量差则搜索/匹配效果差。
- **缓解**：① 立即向需求方索取原始数据表并核对行数/字段；② 清洗按 05 §12 映射表执行，完成人拆分 + `uk_inventor(name, org_name)` 去重；③ 成熟度归一规则表（05 §3.1）先清洗 20 条抽样验证再全量；④ 清洗脚本入库 `tools/`，可重复执行。
- **应急预案**：数据无法获取 → 以演示 3 条成果 + 首批运营录入数据起步，223 条延后导入（架构不受影响，仅影响初期内容量）。
- **触发信号**：阶段 C 开始前未拿到数据文件。

### R-06 AI 假数据回退惯性

- **描述**：演示期的哈希假评分（`buildFallbackEval`）与固定话术（`buildDemoReply`）在 AiProvider 未签约/超时场景下被"顺手保留"，正式用户看到不可解释的假分——信任损失不可逆。
- **缓解**：① 设计层已封死：正式模式任务 failed + `TT_AI_50201`/`TT_AI_50301`，无假分路径（04 §5.2）；② 前端假分函数文件随阶段 B ⑧ 一并删除；③ 阶段 E 验收用例显式包含"Provider 停机 → 页面显示不可用而非假分"。
- **触发信号**：`rg "buildFallbackEval|buildDemoReply" subpackages/` 命中即违例。

### R-07 幂等与状态机实现缺口

- **描述**：对接意向重复创建、双开页面并发操作、网关重放是小程序场景高频问题；实现缺口直接产生脏数据（重复意向/状态跳变）。
- **缓解**：① 幂等三件套已进设计：X-Idempotency-Key + 唯一约束 + 活跃意向 SELECT 校验（06 §10）；② 状态流转全部乐观锁 + 后端状态机矩阵（06 §5.5）；③ 阶段 B 联调负向用例（07 §3.3）与阶段 E 状态机专项测试双重覆盖。
- **触发信号**：联调期间出现同一目标重复活跃意向，或 audit_log 出现矩阵外状态跳变。

### R-08 网关可信头伪造（C-03 分叉）

- **描述**：若上级网关采用"注入 X-User-Id 可信头"方案而科转通服务可被外网直连，攻击者可伪造任意身份——全部权限模型失效。
- **缓解**：① 设计已声明：可信头方案下服务仅接受网关内网来源（网络隔离/mTLS，08 C-03）；② 无论哪种方案，bootstrap 仍走验签，不裸信头；③ 阶段 E 渗透测试必含"绕过网关直连服务伪造身份头"用例。
- **触发信号**：C-03 确认为可信头方案且网络隔离未同步落实。

### R-09 密钥泄漏

- **描述**：AI Key、专利 SaaS 账号、DB 密码进入前端代码、仓库或日志。当前仓库已有 `db_config.json` 明文 root 密码先例（01 §10 S6）。
- **缓解**：① 密钥只存服务端环境变量；② 仓库密钥扫描（CI 简单正则：sk-/apikey/password 等）+ 立即替换现有 db_config.json 为环境变量读取（阶段 B 一并处理）；③ 日志脱敏拦截器（05 §10）覆盖 external_api_log。
- **应急预案**：泄漏即撤销密钥并轮换；受影响审计日志标记。
- **触发信号**：CI 密钥扫描命中。

### R-10 业务分包体积超限

- **描述**：微信单个分包上限 2MB（含静态资源）；科转通分包含 11 页面 + 组件 + 图片。
- **缓解**：① 分包静态资源预算 1.5MB 内；② 大图（banner 等）走 CDN/对象存储 URL 而非打包；③ 构建脚本输出分包体积，CI 超限告警。
- **触发信号**：分包体积 > 1.7MB。

### R-11 单人后端关键人风险

- **描述**：一期后端实际 1 人，模块化单体 15 模块的单点依赖；请假/离职即停摆。
- **缓解**：① 本文档集 + openapi.yaml 即交接基线（契约先行降低了理解成本）；② 关键模块（identity/cooperation/ai）设计文档含事务与状态机细节（04），接手者按文档可实现；③ 阶段 E 前安排一次"按文档独立部署演练"验证文档自足性。
- **触发信号**：核心模块连续 2 周仅一人可修改。

### R-12 旧数据事故复发

- **描述**：`tools/nanshan_capital_backup.sql`（GBK 损坏）仍在仓库，误导入会产生乱码数据（已发生过，见 project 教训）。
- **缓解**：① 该文件头尾已无可执行注释标记的风险——直接**删除**该损坏文件（保留干净版 `nanshan_capital_backup_utf8.sql`），阶段 B 数据迁移时执行；② `import_data.py` 是唯一重导入口径。
- **触发信号**：无需监控，删除即消除。

### R-13 上级 ID 体系变更

- **描述**：上级 open_id 换 union_id、ID 回收重发等（真实发生过的小程序平台行为）。
- **缓解**：ADR-002 身份映射层即为此设计——变更只影响 external_identity 映射行，业务表零改动；映射表支持软解绑重绑（05 §2.2）。
- **触发信号**：上级通知任何 ID 体系调整。

### R-14 基础设施触发条件误判

- **描述**：两个方向都可能错：过早引入 ES/Redis 集群/K8s（违反 02 §9 决策、增加运维负担），或数据增长后过晚扩容（搜索 P95 劣化）。
- **缓解**：02 §9 表格即为触发条件登记处；每季度复核数据规模与 P95 指标，达到触发条件才引入对应设施并同步更新 ADR-003。
- **触发信号**：成果 > 5 万条 / 搜索 P95 > 500ms / AI 任务日量 > 1 万（任一）。

## 3. 风险复查机制

- 每双周项目例会过一遍 §1 总览表状态列（新增/升级/关闭）；
- 任何风险等级升为"高"需当日指定责任人与缓解截止日期；
- 风险关闭需给出证据（CI 通过记录/测试报告/确认函），不接受口头关闭。
