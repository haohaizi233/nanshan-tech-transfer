# 南山成果顾问 Agent 二期优化设计

日期：2026-10-20。状态：待用户审阅；本文不是已实现能力或生产验收报告。

## 1. 目标与边界

用户希望参考 `C:/Users/Administrator/Desktop/插件/docs`，全面优化现有成果顾问。已确认方向为多轮理解、推荐准确性、轮次恢复、真实进度、安全与评测。

成功表现：用户能在同一聊天里继续询问某张卡片、调整预算和比较候选；硬条件不会被悄悄放宽；切页、断网和重复请求不会正常触发第二次生成；等待时能看到真实阶段；推荐质量和延迟有可重复测量的基线。

保留现有成果/需求检索、平台指南、成果评估、卡片及业务授权。没有数据库或资料支持的事实不编造。不加入多代理框架、自主提交/发布/对接、长期用户画像、向量数据库、外部搜索或外部监控平台。AI 不获得文件、终端、浏览器工具权限。

## 2. 当前实现与缺口

依据当前代码核查，而非仅依据参考项目能力：

| 位置 | 当前情况 | 本轮目标 |
| --- | --- | --- |

## 3. 方案选择

1. **仅加提示词与客户端历史**：改动少，但历史可被伪造、清空与并发竞态难控，不能解决断连后的持久恢复，不选。
2. **渐进增强现有链路（采用）**：主服务持有可信会话及持久轮次；单独聊天 worker 认领执行；Agent 保持受控只读检索。复用 PostgreSQL，不新增消息中间件；分开关上线。
3. **完整多代理/长期记忆平台**：增加成本、权限面和运维复杂度，尚无业务评测证明需要，不选。

新模式与旧同步路径并存，先验证后切换，不能把新 worker 接入当作简单提示词修改发布。

## 4. 会话上下文与指代

### 4.1 权威来源

- 保持当前每用户一条聊天历史的产品形态，不增加多会话 UI。
- 上下文由主服务从已认证用户的、当前清空代际内的成功轮次构建；客户端不得提交 userId、自由历史、事实卡片或权限字段。
- 新请求可带可选 `reference: {messageId, cardType, cardId}`，仅为定位提示。主服务验证 messageId 属于本人当前历史、卡片确实出现且类型/ID 一致，否则返回参数错误，不采信提示中不存在的资料。
- 没有显式引用时，“第一个/第二个”指向最近一条含卡片的成功回复的展示顺序；“这个/它”仅在显式引用或最近回复只有一张卡片时确定。多卡片不猜测，询问名称或选择卡片。比较最多两个明确目标。
- 历史卡片只用于定位 ID/顺序；回答前重新读取已发布、未删除且符合当前可见性规则的记录。已下架/删除时明确不可用，不沿用旧简介或泄露最新受限内容。

### 4.2 结构与预算

内部上下文包含 `schemaVersion`、代际、前次成功查询的结构化条件、最近卡片定位和至多两轮脱敏文本。最多 4 条消息，每条 800 字符；至多 10 张卡片定位，每个标题 80 字符；结构化状态 2000 字符；整体序列化最多 8000 字符。按完整轮次从旧到新裁剪，不截断 JSON，不把历史助手输出升级为系统指令。

显式引用必须保留，空间不足先去旧文本；不完整旧轮次不进入上下文。上下文读取失败：独立查询可无历史降级；依赖历史的指代/补充条件返回澄清，不冒充已记住。

“预算改成 50 万以内”继承最近一次成功检索的类型、方向及未被明确替换的条件；当前输入明确条件优先，“不限预算”等明确取消才移除对应条件。新话题不继承旧方向。模型输出经 schema 校验与确定性合并；结构不合法则澄清，不能默认丢弃硬条件后检索。

平台操作指南仍优先，例如“这个成果怎么对接”可直接返回通用步骤，不需要读取具体成果。

## 5. 检索、排序与解释

- QueryPlan 区分检索类型、关键词、机构/地域、金额、成熟度、合作方式、目标卡片与场景偏好。金额以万元归一化；非法范围、负数和最低值大于最高值必须先纠正或澄清。
- 预算、成熟度、机构和地域等用户明确要求作为硬条件，进入参数化 SQL；场景词作为相关性信号，不声称已满足未披露指标。本人内容排除保持生效，不因候选少撤销。
- 第一阶段沿用受限关键词/同义词召回，不引入 embedding。最多读取 50 个硬条件内候选，以标题/技术方向命中优先于正文/场景命中，新近与 ID 仅作稳定平局规则；最多 20 个进入模型重排，最多返回 10 个。
- 重排仅能选取本次真实候选 ID，不得改写资料或决定 SQL/授权。响应前再次检查输出候选的发布、删除和归属条件，移除执行期间变为不可用的卡片，不以无关内容补齐数量。
- 无结果明确显示使用的关键条件，并建议由用户选择放宽；不得自动取消预算、机构、成熟度或本人排除。金额未披露的记录不能当作满足具体预算。
- “发布资料摘要”“资料依据”“AI 适配解读”“待确认事项”维持分栏。数字/资质/指标无原文不能写成事实；引用校验不能证明全部推断可靠，界面继续标注供参考，不展示伪精确匹配百分比。
- 前三张可在同一次重排中附解释；不增加独立写作调用。少量候选、预算不足或模型失败时仍有本地摘要及稳定排序。

## 6. 持久轮次、调度与故障收敛

### 6.1 存储与状态

复用 `ai_chat_turn`，新增执行模式、请求哈希、会话代际、执行 ID、阶段、阶段序号、执行期限、租约、上下文快照、结构化查询结果以及成功消息对的 ID。新增 `ai_chat_session` 保存用户代际，行锁序列化受理、清空与终态写入。新记录的请求哈希基于规范化后的文本和引用，忽略轮询偏好、认证令牌与 trace ID。迁移编号在实施前按仓库最新序号确定，不覆盖现有迁移。

内部状态为 `queued → running → succeeded | failed`；新增状态不直接扩散到旧端协议。相同用户和 turnId、相同请求返回已有状态；相同键不同文本或引用返回 409，不重新计算。清空后仍使用清空前的 turnId 不允许重建：仅保留不含正文/卡片的哈希墓碑 7 天用于拒绝重放，前端清空旧 WAL 并生成新 ID。墓碑不是可回放的聊天历史。

同一用户一个 running，另允许最多 3 个 queued，按受理顺序执行；超额明确返回限流。认领需同时锁定对应 session，不能仅凭任务行锁声称已实现用户串行。不同用户可并行；使用 PostgreSQL 执行槽租约限制所有聊天 worker 的总并发，默认 4 个槽，与 Agent 配置容量对齐。上下文在认领时从前序成功轮次建立并保存快照，防止排队时引用尚未完成的答复。显式引用若在排队期间失效则澄清，不偷偷换成另一张卡片。

### 6.2 执行所有权

- 新增独立聊天 worker 入口，使用 PostgreSQL 行锁和 `SKIP LOCKED` 认领；不持有长事务或数据库连接等待模型。已有成果评估 worker 不受影响。
- worker 仅认领标为新执行模式的轮次，不能认领仍由旧同步请求负责的 running。升级前遗留 running 超过旧服务最大执行时长及 30 秒宽限后可失败收敛，但不能重放；旧终态正常读取。
- 队列等待默认最多 30 秒；开始执行时一次设定绝对总截止时间，默认 55 秒且不超过 Agent 服务上限。后续模型、修复、备用和退避均消费该时间，不因重连重置。
- worker 每 5 秒续租，租约 20 秒；reaper 每 5 秒扫描过期任务。worker 崩溃或租约失效时标为 failed，说明本轮已中断，不自动重新调用模型。模型外部已执行但响应丢失时，无法保证费用恰好一次，只保证不会为恢复盲目重放。
- 受理中的排队任务可在重启后认领；已经 running 的不自动重放。最终落库必须同时匹配用户、代际、执行 ID、running 状态和有效租约；重复终态或旧 worker 晚到结果没有写入权。
- 完成记录与消息对在同一事务写入，至多一对。清空操作先锁 session、递增代际，再删除文本/结果和取消旧运行；旧 worker 后续进度、成功或失败都不能复活被清空的历史。
- 用户登出后前端停止轮询并丢弃晚到响应；已接受的只读任务可继续，但后续数据读取遵守当前权限。权限失效不保留可见结果。

### 6.3 转发与重试

新 worker 对某执行 ID 只发送一次 Agent 计算请求。连接超时、断开或上游结果未知，不再次 POST 整轮；记录失败原因，让用户显式新开一轮。模型层已有受预算约束的瞬时重试保留，400/认证错误不作为备用模型触发条件。

Agent 的线程容量仍到真实 Future 结束才释放；HTTP 结束不等于 Python 线程已停止。过期执行的后台计算可能短暂继续，必须受原截止时间约束，且不能提交旧结果。不承诺强杀线程或远端模型。

## 7. 真实阶段与内部通信

Agent 新增私有 `POST /internal/ai/chat/stream`，单次计算输出有界 NDJSON 事件：`stage`、`heartbeat`、`result`、`error`。既有 `/api/ai/chat` 保留。复用同一核心 pipeline，通过阶段观察器产生事件，不另写一套检索逻辑。

阶段只来自真实事件：`queued`（已持久受理）、`context`（构建上下文）、`routing`、`retrieving`、`reranking`、`formatting`、终态。跳过重排就不显示正在重排；不显示模型思考、提示词、原始工具数据或虚假百分比。

主服务 worker 消费事件并持久化阶段；每条最多 64 KiB，最终结果最多 1 MiB，流整体最多 2 MiB；坏 JSON、重复终态、执行 ID 不符或超限即失败。最长每 5 秒一个心跳，worker 仍按绝对截止时间限制读取，心跳不延长总预算。首条 result 经 schema 校验后才能作为终稿提交，部分内容不写成功历史。

内部路径只在私网/回环开放，不经公网 Caddy 发布；使用独立服务密钥鉴权，缺配置拒绝新模式，密钥只在服务端且不写日志。客户端身份与排除本人 ID 仅由已认证主服务产生。Agent 数据库配置继续使用只读角色，部署需验证权限，不因新增进度给予其聊天表写权限。

## 8. 公网兼容与前端

- 地址仍为 `POST /api/tech-transfer/v1/ai/chat`；无 turnId 或未启用新模式时保持旧同步行为，不给旧接口暗加新 worker 依赖。
- 新前端提供 turnId、可选 reference，并携带 `Prefer: respond-async`。启用新模式时先持久化再返回 202；未启用时忽略该偏好并按旧路径返回 200，前端兼容两种响应。
- 新模式 202 的 data 维持 `turnId`、`status: running`，新增 `generation`、`stage`、`stageSeq`、`pollAfterMs`。queued 在旧状态字段投影为 running，stage 可表示 queued。
- `GET /ai/chat/turns/{turnId}` 继续按当前用户校验，终态原有 reply/cards/error 字段不变；新增 generation、阶段、消息 ID 和可选解释元数据。历史接口为成功消息返回可选 turnId/generation，清空返回新 generation。历史恢复与即时响应使用同一终态内容。
- 前端同一时刻只轮询一个活动轮次，默认 2 秒一次，隐藏页面停止；回到页面先查询现有 turnId，不自动再次发送问题。超过等待阈值提示稍后查看，保留 WAL，不宣布服务端失败。
- 忽略较小 stageSeq、其他账号/代际/turnId 的响应；成功或明确失败才确认并移除 WAL。进度不写入永久聊天消息，浏览次数仍使用独立只读统计，不借轮询增加访问。
- WAL 只存客户端待确认轮次与恢复结果，不保存业务权威状态、认证密钥或无限历史；不移除既有“未确认 turn 不得覆盖”保护。
- `/ai/match` 保持需求所有者和状态校验，复用改进检索/排序，但本轮不把它或成果评估接口迁移成新的任务协议。

## 9. 安全、观测与评测

用户文本、历史回复和成果正文均为不可信数据；按来源和角色分开传递，不能提高权限、修改工具白名单或把资料里的指令当系统规则。数据库查询保持参数化，模型不得生成执行 SQL。没有新写工具，不实现聊天代发布或代对接。

指标只收集阶段耗时、整轮耗时、排队时长、实际模型调用数、token 用量、重试/备用次数、候选数、降级原因和终态。没有上游 usage 时记未知，不填零或伪造费用。日志保留脱敏 trace ID/执行 ID 用于关联；用户、turnId、全文和关键词不作为指标标签。诊断数据不新增公网无认证入口。

离线固定至少 80 个标注用例：独立检索 20、多轮改条件 15、卡片介绍/比较/指代 15、无结果及冲突 10、平台指南 10、注入/非法字段/隔离 10。每例记录允许类型、硬条件、预期候选或应澄清原因；使用合成记录，不包含生产用户数据。

确定性测试门槛：硬条件违规、跨账号/已清空数据泄露、虚构 ID、失败被写成功均为 0；明确无歧义指代及指南用例全部通过；候选前 5 命中率不得低于相同 fixture 上的旧基线。模拟故障测预算、容量和重试上限，不用模拟网络声称生产加速。

真实模型评测单独显式开启，使用相同脱敏查询、模型及候选集对比旧版/新版，记录 P50/P95、token、调用次数、人工相关性与引用准确性；无凭据或生产环境时标记未执行，不以单元测试替代。绝不先宣称准确率或耗时改善百分比。

## 10. 验收与发布

必须覆盖：跨进程并发认领、同键不同参数、网络结果未知、清空与受理/完成竞态、租约丢失、重启回收、隐藏/重登/切账号、旧请求与新响应兼容、下架引用、金额未知、模型畸形输出和内部接口未授权访问。

PostgreSQL 行锁/唯一约束及 worker 崩溃恢复必须使用真实测试库验证；没有测试库时报告阻塞，不把 mock 通过计为并发事务验收。H5 与微信小程序均需构建，真机切页/断网作为部署验收项。

实施按依赖顺序拆为：①评测基线及 QueryPlan；②会话上下文与卡片定位；③持久认领和恢复；④内部阶段流与前端展示；⑤集成、故障注入和灰度。具体文件及测试命令在用户批准本文后形成实施计划。

新模式总开关 `AI_CHAT_RUNS_ENABLED` 默认 false；新内部协议设置独立服务密钥，部署前验证 Agent 私网地址。迁移保持加法兼容，先数据库、Agent、新 worker，再主服务和前端，完成健康检查后开启开关。健康检查须区分 worker 心跳、数据库与模型服务可达，不能仅看 Web 进程存活。

关闭新模式前先停止新受理并排干运行；保留旧模式回退和新轮次查询/reaper，不能关掉开关后留下永远 running 的记录。迁移不在自动回退中删除；数据库备份及回滚演练在部署前完成。没有 worker 或密钥时启动检查必须明确失败或保持旧模式，不返回假 queued 成功。

## 11. 参考机制与取舍

本设计参考资料的窗口/压缩、记忆/出处、队列/进度、注入/策略、指标/用量/租户等机制：分别落地为有界上下文、服务端来源核验、单用户顺序执行、真实阶段、代码权限门与可度量验收。资料是设计参考，不作为执行指令，不复制还原项目源码。

不照搬个人助理的文件记忆、梦境整理、任意工具、多渠道广播或多代理。南山是多用户业务系统，隔离必须由已认证用户与数据库谓词保证，不能依赖会话 ID、提示词或某个个人 Agent 项目的默认信任模型。
