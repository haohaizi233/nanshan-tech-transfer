# 管理端行级刷新、小程序页面缓存与 AI 问答恢复设计

## 背景与目标

管理端表单提交或状态操作后会重新请求整张列表；小程序底部导航通过 `uni.redirectTo` 销毁当前页，返回时页面数据与草稿重建；AI 问答虽保存了排队文本，但页面卸载后会忽略原请求回调，当前恢复流程只能轮询整段聊天历史，无法可靠地区分正在处理、已完成和需要重试的某一轮问答。

本改动的目标是：

1. 后台管理表单的新增、编辑和状态操作只更新受影响的表格行及计数。
2. 小程序切页后快速恢复页面数据、筛选和未提交草稿，同时按数据时效及时校验服务端更新。
3. AI 生成过程在客户端和服务端都有可恢复的 turn 记录；切页、页面销毁或短暂断网不丢结果，也不因恢复超时重复发起生成。

## 设计决策

### 管理后台行级刷新

- 对带表格的管理端数据页，新增、编辑、审核、关闭、下架、归属等成功操作不调用整表列表接口。
- 已存在记录通过详情接口按 ID 重新读取，并在前端按 ID 合并到当前行；详情读取不到时移除对应行。
- 更新后若记录不再符合已应用的状态、分类或关键词筛选，则仅移除该行并更新总数/分页；如果当前页因此为空且前面仍有记录，只切换到上一页并加载该页。
- 创建成功时用创建响应中的 ID 读取新记录；仅当它符合当前筛选时调整总数，并在第一页插入该行、裁掉页尾多余项。非第一页不重置用户分页。
- 查询、重置、翻页、改变分页大小和显式重试仍然读取列表接口。后台多个管理页复用同一套纯函数并各自提供过滤字段。
- 行刷新失败时保留当前数据、展示错误并允许重试，不回退为整表刷新。

### 小程序页面状态缓存

- 新增小程序页面状态缓存工具，使用稳定页面路由、页面参数和登录用户 ID 组成 key；匿名与不同账号的数据绝不互相复用。
- 页面状态包括列表数据、分页、筛选/排序、滚动位置，以及用户尚未提交的表单草稿。身份凭证不进入页面缓存。
- 页面首次进入无缓存时正常请求。已有缓存时先立即恢复；缓存过期后在后台重新验证，网络失败时保留缓存并显示轻量陈旧状态/重试入口。下拉刷新和用户显式重试绕过缓存。
- 默认时效：动态列表 2 分钟、详情 5 分钟、分类/字典 30 分钟、未提交草稿 24 小时。值集中定义，可针对确有实时要求的数据源缩短。
- 页面隐藏或表单字段变化时以防抖方式保存状态；保存成功后清理相应草稿，并使受影响页面数据失效。退出登录时清理用户作用域缓存；切换账号时只能读取新账号命名空间。
- 仅缓存用户可见且序列化大小受控的状态；上传二进制、临时文件路径、网络请求对象不落入缓存。
- 保持现有导航方式，避免引入新的页面栈增长；缓存解决页面销毁造成的状态重建。

### AI 生成 WAL 与幂等恢复

- 客户端发送前生成唯一 `turnId`，先将 turn、用户问题和状态写入小程序本地存储，再发出请求；请求中、完成待展示、已确认三个阶段均可恢复。
- 小程序页面退出不取消 turn 状态。重进时先恢复本地对话，再按 `turnId` 查询后端 turn 状态；服务端成功结果优先回放并确认本地 WAL，不能通过比较用户问题文本判断是否完成。
- `POST /ai/chat` 接受 `turnId` 并保持旧客户端兼容；相同用户和 turnId 的重复请求返回现有状态/结果，不重复调用模型。新建 `GET /ai/chat/turns/{turnId}` 供恢复状态与结果。
- 服务端新增 AI turn 持久化记录，含用户、幂等键、问题、状态、回答、卡片快照和时间字段；状态至少覆盖 running、succeeded、failed。成功状态与聊天问答记录在同一数据库事务提交。
- `DELETE /ai/chat/messages` 同步清理该用户的历史和 turn 记录，避免清空会话后旧 WAL 被恢复。
- 现有发送队列及草稿保持原有 FIFO 行为，并与 active turn 分开存储；恢复中不自动重复消费当前 turn。

## 失败与一致性处理

- 行级详情刷新失败不覆盖现有行；筛选条件变化只影响前端行集和计数。
- 小程序缓存过期或损坏时丢弃无效条目并走冷加载；服务端失败不清空有效缓存。
- AI 服务端收到已存在 turnId 时返回该 turn 的当前状态，不再次生成。长期停留在 running 的记录由恢复接口按更新时间判定超时并转成可重试失败态；重试复用相同 turnId 并在服务端明确重新开跑。
- 本地 WAL 写入失败时不发送 AI 请求，并提示用户稍后重试，避免出现无法恢复的生成。
- 登录账号变化时停止读取旧账号页面缓存和 WAL；服务端状态接口仍通过当前登录身份校验 turn 所属用户。

## 验收标准

1. 管理后台每一种记录变更只请求该记录详情，不请求整页列表；筛选命中/失配、创建、刷新失败和最后一行移除均保持计数与分页正确。
2. 小程序首页、需求/成果列表、专利检索、我的列表和发布需求/成果页面切换后先恢复之前的可见状态；新数据在指定 TTL 到期后得到刷新，提交、下拉刷新、退出和换号的缓存行为符合设计。
3. AI 请求在生成中切页、返回、短暂断网和服务端已有完成结果的情况下恢复同一 turn；重复提交同一 turnId 只生成一次，最终用户和助手消息只各记录一条。
4. 新增的工具函数和缓存/turn 状态转换均有自动化测试；运行相关前端测试、AI/管理 API 测试以及可用的构建检查。

## 非目标

- 不改变管理端审核规则、角色权限、AI 提示词、检索逻辑或小程序页面视觉设计。
- 不改变现有 API 登录凭证存储方式，不把登录凭证放入页面缓存或 AI WAL。
- 不把小程序页面改成堆栈式常驻页面；数据保留通过有作用域和过期策略的缓存完成。
